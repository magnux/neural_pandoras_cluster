\section{Discussion: What Has Been Learned?}
\label{sec:discussion}

\subsection{What it means for a system to model itself}
\label{sec:recursive-discussion}

What would count as predicting the behavior of the first model? Choose a view of the mosaic and move it a fraction of a patch. Even where the two views overlap, the encoder now sees a different crop and generally returns a different code. The gencoder predicts those new responses from a corrupted window of the old ones. We can check a prediction in either of two ways: compare it with the codes the fixed encoder actually returns, or decode it and inspect the view it describes. The archived objective uses the first comparison; the sampled sequences use the second to make the predictions visible.

These two comparisons are available because the bottleneck is an interface between trained networks: the encoder writes a code there and the decoder can turn it back into a patch. Predicting a hidden activation earlier in the encoder would ask a different question about the same network. What makes this representation-level self-modeling is the source of the targets. They are observations of the system's own encoder on this dataset. The gencoder need not infer its weights or reproduce its response to every possible input.

Our longer-term hypothesis is that recursion of this kind could contribute to artificial general intelligence. For a third level to be useful, there would have to be a relationship available across second-level representations that its training objective rewards it for learning. In the mosaic, for example, one could ask whether a sequence of views disambiguates locations that look alike in any single view. That would give a further level a specific prediction to make. Only the patch model and the gencoder were trained here.

\subsection{Which information survives?}

An ordered grid of patch codes and a model that predicts plausible code neighborhoods serve different purposes. The grid records which patch occurred at each indexed location. The gencoder can learn regularities in that arrangement without storing a unique address for every patch. Where two regions look alike, their likely continuations may also be plausible alternatives to each other. A trajectory can therefore remain locally coherent even after it loses its place in the source, one possible explanation for the reported jumps.

There is also a limit set by the encoder. If two distinct patches map to the same code, no model given only that code can determine which patch was encoded. Neighboring codes may provide the missing clue, but only if those neighbors retain distinguishing information. Additional levels can make retained relationships usable; adding a level is no guarantee that lost distinctions can be recovered.

\subsection{Where does the reconstruction program live?}
\label{sec:compression}

In Sanderson's account of lossless text compression~\cite{sanderson2026}, an encoding program writes a message and a decoding program recovers the text. If the receiver does not already have the decoder, its size matters alongside the message. ReGAE suggests another way to read this arrangement: the encoder writes a \emph{program for the decoder}. The learned weights and the code are all numerical data. The encoder weights determine how to write a program from a patch; the decoder weights define an interpreter shared across patches. The particular $z$ selects how that interpreter updates a state (Sec.~\ref{sec:direct-map}). To understand the behavior of the whole system, we have to ask what work is done by each of the three. Code width and parameter counts alone cannot answer that question.

Consider a faint star next to a bright galaxy. One design could give the encoder enough capacity to resolve the star and a wide code to specify its position and brightness. A relatively simple decoder could render those details. Another design could use a simpler encoder and a short code to select a galaxy profile that a more expressive decoder has learned to draw. Such a decoder can produce considerable detail from a few numbers. But if moving the faint star leaves the code unchanged, decoding from the same initial state cannot reveal which position occurred. Fresh noise can supply texture without restoring that missing observation.

The choice depends on what the reconstruction is for. Recording a one-pixel shift matters if the position of the star is the target. Ignoring a background fluctuation can be desirable if two noisy observations should produce the same smooth reconstruction. The encoder, the width and precision of its code, the decoder, and the training loss together determine which distinctions the system can express and which it learns to preserve. We did not vary these capacities to measure a trade-off. The gencoder asks a different question: given the programs the encoder wrote for one view, which programs will it write for a neighboring view?

The 12-fold reduction in coordinates is a property of the patch representation. Assigning a bit rate to it would require a precision and a coding rule. One could quantize and entropy-code the latents, or code errors against a predictor~\cite{lmcompression}; neither step is part of this work. The gencoder predicts real-valued neighbors under an $L_1$ loss, without encoding the errors needed to recover the observed grid. Appendix~\ref{sec:storage} separates code and model storage; a codec comparison would also require matched reconstruction error~\cite{mdl,coin}.

\subsection{What the experiment establishes}

The notebooks document a two-level construction and training losses for both the pixel and code objectives. The trajectories described in Sec.~\ref{sec:evidence} are the author's observations from the original runs; the corresponding frames are not in the archive. The loss curves therefore answer a narrower question than the visual account. They do not tell us how closely a trajectory follows the source, or how much perturbation the decoder can undo. In particular, the final video routine calls the image decoder once per patch while feeding predictions back at the latent level. It illustrates the gencoder's role in synthesis; it does not measure pixel-space regeneration.
